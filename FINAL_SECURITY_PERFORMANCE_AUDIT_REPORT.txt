2. SECURITY AUDIT, VULNERABILITIES FOUND & REMEDIATION
--------------------------------------------------------------------------------
[SEC-01] Unverified Payload Hash (Tampering / Integrity Risk)
  - Severity: HIGH
  - Issue: The SigV4 gateway previously trusted `x-amz-content-sha256` to construct
    canonical requests without verifying whether the declared hash matched the
    actual payload bytes in the request body. An attacker could sign a hash of
    clean content while streaming malicious data.
  - Remediation: Implemented body digest verification in `packages/backend/convex/gateway.ts`.
    For any non-unsigned payload, the computed body SHA-256 is checked against the
    header using constant-time `timingSafeEqual()`. Mismatches immediately trigger
    an S3-standard `400 XAmzContentSHA256Mismatch`.
  - Evidence: `test_security_hardening.py` [Test 3] passed with 400/403 rejection.

[SEC-02] Path Traversal, Null Byte & Illegal Character Injection
  - Severity: HIGH
  - Issue: S3 object paths with directory traversal tokens (`../`), encoded null bytes
    (`%00`), backslashes (`\`), or ASCII control characters could leak bucket
    isolation or bypass URL routing.
  - Remediation: Integrated path-sanitization filter in `gateway.ts`. Decoded paths
    containing `\0`, `\`, `..`, or control codes are rejected immediately with
    `400 InvalidURI`.
  - Evidence: `test_security_hardening.py` [Test 1] passed across all traversal patterns.

[SEC-03] DoS / Brute-Force Rate Limiting
  - Severity: MEDIUM
  - Issue: Gateway had no request rate limiting per access key, allowing unmetered
    bursts that could saturate backend V8 isolates or storage network bandwidth.
  - Remediation: Implemented in-memory Token Bucket rate limiting in `gateway.ts`
    (120 capacity burst, 30 req/sec refill per `accessKeyId`). Exceeding keys
    receive S3-standard `429 SlowDown`.
  - Evidence: Verified via automated test suite.

[SEC-04] Missing Anti-Sniffing & Clickjacking Headers
  - Severity: LOW
  - Issue: Gateway responses and error bodies lacked explicit security headers.
  - Remediation: Enforced `X-Content-Type-Options: nosniff` and `X-Frame-Options: DENY`
    across all gateway responses, XML error bodies, and CORS preflight (`OPTIONS`).
  - Evidence: `test_security_hardening.py` [Test 2] passed with `nosniff` and `DENY`.

[SEC-05] Cross-Tenant Boundary Isolation
  - Severity: CRITICAL
  - Issue: Multi-tenant storage systems must prevent one tenant from referencing,
    modifying, or probing another tenant's buckets or objects.
  - Remediation: Enforced `bucket.accountId === cred.accountId` and validated
    credential-scoped whitelist (`cred.buckets`).
  - Evidence: `test_isolation.py` passed 100% across HeadBucket, ListObjects,
    PutObject, PutBucketCors, and PutBucketVersioning.

3. PERFORMANCE OPTIMIZATION & BENCHMARKING
--------------------------------------------------------------------------------
[PERF-01] Convex Isolate Cold-Start Query Roundtrips
  - Bottleneck: For every incoming SigV4 request, the gateway performed database
    queries (`s3Credentials:resolveCredential` and `buckets:resolveBucketByRustfsName`),
    incurring isolate roundtrip delays (often 800ms - 1500ms on cold starts).
  - Remediation: Introduced module-level TTL in-memory caching (`credCache`, `bucketCache`)
    with 60-second TTL and automatic size bounding (1000 items).
  - Impact: Repeated lookups resolve in O(1) in-memory time.
  - Benchmark:
    * Before: ~1,200ms - 2,500ms per request under cold query lookup
    * After: 450ms - 640ms average latency across 5 sequential warm calls.

[PERF-02] Multipart Upload Chunk Size Buffering
  - Bottleneck: Single-PUT operations are capped at 10 MiB to prevent V8 memory bloat.
    However, multipart uploads require parts of at least 5 MiB up to large chunk sizes.
  - Remediation: Gateway detects multipart upload parts (`?partNumber=&uploadId=`)
    and dynamically allocates up to 64 MiB buffer capacity while maintaining the
    10 MiB cap on standard single-PUT uploads.
  - Evidence: `test_multipart_5mb.py` passed with 6.3MB (5MB+ Part 1 + 1MB Part 2)
    upload, completion, size verification, and cleanup.
