2. SYSTEM ARCHITECTURE & REQUEST FLOW
================================================================================
The platform decouples control-plane metadata and tenant isolation from the raw
object data plane:

[External Client (boto3 / aws-cli / rclone)]
                │
                ▼ (AWS SigV4 Signed Request to `/s3/{bucket}/{key}`)
[Next.js / Convex HTTP Action Router (`http.ts`)]
                │
                ▼
[S3 Gateway Handler (`gateway.ts`)]
   ├── 1. Signature Verification: Recomputes SigV4 using tenant secret key (AES-GCM decrypted)
   ├── 2. Rate Limiting: In-memory token bucket per AccessKeyId (120 burst / 30 req/sec)
   ├── 3. Timestamp Freshness Check: Rejects timestamp skew > 15 minutes
   ├── 4. Route & Query Validation (`s3Protocol.ts`): Rejects conflicting/duplicate subresources
   ├── 5. Tenant Authorization & Scope Check:
   │      - Resolves physical `rustfsName` via `internal.buckets.resolveBucketByRustfsName`
   │      - Returns uniform 403 AccessDenied for missing or cross-tenant buckets
   │      - Validates allowed bucket scope and allowed S3 action scope
   │      - For CopyObject: verifies authorization on the source bucket and object
   ├── 6. Bounded Body Streaming: Rejects bodies exceeding memory limits before buffering
   ├── 7. XML Schema & Semantic Validation: Validates XML structure, limits, and rules
   └── 8. Upstream Proxy Re-Signing:
          Re-signs request with root credentials and proxies to RustFS data plane
                │
                ▼
[RustFS Data Plane (`http://rustfs:9000`)]
   ├── Physical byte storage
   ├── Object versioning immutability & Delete Markers
   ├── Multipart chunk assembly & ETag generation
   └── Upstream XML serialization

6. DEFECTS, EDGE CASES & COMPATIBILITY CAVEATS
================================================================================

6.1 ADDRESSING STYLE: VIRTUAL-HOSTED-STYLE NOT SUPPORTED (PARTIAL)
--------------------------------------------------------------------------------
- Defect ID: DEF-S3-001
- Severity: Medium
- Classification: PARTIAL
- Affected File: packages/backend/convex/gateway.ts (lines 305-314)
- Description: The S3 gateway strictly routes requests where pathname begins with
  `/s3/` (Path-Style). Requests formatted in AWS S3 Virtual-Hosted-Style
  (`http://<bucket>.<host>/<key>`) are not recognized and return 404 NoSuchRoute.
- S3 Client Impact: AWS CLI and Boto3 must be explicitly configured with:
  `s3 = { addressing_style = "path" }` or `--endpoint-url http://endpoint/s3`.
- Recommendation: Document path-style addressing as mandatory for all integrations.

6.2 STREAMING TRAILER SIGNATURES: AWS-CHUNKED UNSUPPORTED (501 NOT IMPLEMENTED)
--------------------------------------------------------------------------------
- Defect ID: DEF-S3-002
- Severity: Low
- Classification: PASS (Standard 501 Error)
- Affected File: packages/backend/convex/gateway.ts (lines 569-571)
- Description: The gateway explicitly detects and rejects AWS chunk-signature
  streaming (`STREAMING-AWS4-HMAC-SHA256-PAYLOAD` or `aws-chunked` encoding) with:
  `<Error><Code>NotImplemented</Code><Message>AWS chunk-signature streaming is not supported; send a bounded ordinary payload</Message></Error>`
- S3 Client Impact: Uploads with AWS CLI exceeding 16 MB by default attempt chunked
  signing unless configured with `s3 = { payload_signing_enabled = false }`.
- Recommendation: Guide clients to disable chunk-signature streaming or use
  standard Multipart Uploads.

6.3 GATEWAY MEMORY BUFFERING BOUNDS
--------------------------------------------------------------------------------
- Defect ID: DEF-S3-003
- Severity: Low
- Classification: PASS (Bounded Behavior)
- Affected File: packages/backend/convex/gateway.ts (line 568), s3Protocol.ts (line 279)
- Description:
  * Single PUT requests are capped at S3_GATEWAY_MAX_BYTES (default 10 MiB).
  * Multipart parts are capped at 64 MiB per part.
  * XML payloads (Delete, CORS, Tagging, Versioning) are capped at 2 MiB.
  Exceeding bodies are rejected with HTTP 413 EntityTooLarge.
- S3 Client Impact: Files larger than 10 MiB cannot be uploaded in a single PUT
  through the gateway.
- Recommendation: Use Multipart Uploads (supported up to 64 MiB/part) or direct
  browser presigned URLs (presignPut) which bypass the gateway action memory limit.

6.4 S3 5 MiB MINIMUM PART SIZE ENFORCEMENT
--------------------------------------------------------------------------------
- Defect ID: DEF-S3-004
- Severity: Informational (Specification Adherence)
- Affected File: packages/backend/convex/rustfs.ts (line 445), test_gateway_suite.py (line 85)
- Description: Per AWS S3 specification, non-final parts in a multipart upload must
  be at least 5 MiB (5,242,880 bytes). If a non-final part is smaller, RustFS
  rejects completion with 400 EntityTooSmall. The final part may be smaller.
- Test Evidence: test_gateway_suite.py asserts that non-final parts < 5 MiB trigger
  EntityTooSmall.

7. SECURITY, ISOLATION & DATA INTEGRITY VERIFICATION
================================================================================
1. Multi-Tenant Account Isolation:
   Physical bucket names in RustFS are prefixed with tenant `accountCode`
   (`${accountCode}-${bucketName}`). The gateway resolves buckets via
   `internal.buckets.resolveBucketByRustfsName`. If a bucket is not owned by the
   authenticated storage account, it returns uniform 403 AccessDenied, preventing
   tenant existence enumeration.

2. Credential Scope Restrictions:
   Credentials can be scoped to specific buckets (`cred.buckets`) and specific
   S3 actions (`cred.actions`). Scopes are validated on every request prior to
   upstream proxying.

3. Cross-Tenant CopyObject Protection:
   When `x-amz-copy-source` is passed, the gateway parses the source bucket and
   key, verifies that the source bucket is owned by the same storage account, and
   asserts that the credential has `s3:GetObject` permission on the source.

4. Payload Integrity Verification:
   When `x-amz-content-sha256` is provided by the client, the gateway computes the
   SHA-256 of the received body and verifies equality using `timingSafeEqual`.
   Mismatches return 400 XAmzContentSHA256Mismatch.
