PART 2: S3 STORAGE PLATFORM — AUTOMATIC S3 CREDENTIAL PROVISIONING (backend-echo)
(Incorporated from TODAYS_PROGRESS_REPORT.txt)
--------------------------------------------------------------------------------

1. OBJECTIVE
Implement a workflow that creates narrowly scoped application-issued S3 credentials,
securely delivers them to a registered external consumer, persists and reloads its
configuration, verifies gateway connectivity, and supports safe retry and rotation
without manual credential copying.

The concrete consumer selected for this implementation is backend-echo.
This work does not automatically configure arbitrary applications, AWS CLI, or rclone.

2. ANALYSIS AND ARCHITECTURE COMPLETED
Reviewed the credential lifecycle, Convex schema and authorization helpers, SigV4 gateway,
signing primitives, existing RustFS client, credential UI, reference backend, package
configuration, and existing test fixtures.

Confirmed the distinction between:
- Application-issued S3 access keys: authenticate against the /s3 gateway.
- Dashboard/platform API keys: separate from S3 credentials.
- Server-side RustFS credentials: used by the gateway upstream and not intended for
  disclosure to external applications.

Confirmed that Convex cannot directly edit another host's configuration. The proposed
integration therefore uses authenticated server-to-server credential delivery to a
consumer-owned configuration service.

The existing RustFS client replaces URL paths, so it cannot be used unchanged for a
gateway endpoint containing /s3. A consumer gateway client was started using the existing
SigV4 signing primitives.

Planning is recorded in: .planning/automatic-s3-connections.md

3. FILES CREATED
- backend-echo/package.json:
  Added package definition with start and test script declarations. Test directory
  and automated suite have not yet been created.
- backend-echo/s3-connection-store.mjs:
  Added payload validation and connection identifier checks, configurable state-directory
  handling, per-connection JSON files and exclusive filesystem locks, temporary-file writes,
  fsync, rename-based replacement, preservation of unrelated top-level configuration fields,
  stored-record reading, listing, and removal, POSIX permission handling, and an explicit
  unsafe development override for Windows/local development.
- backend-echo/s3-client.mjs:
  Added a gateway-prefix-aware client using the repository's SigV4 signer, signed requests,
  request timeouts, redirect prevention, and limited ListObjectsV2 connection verification.
- backend-echo/s3-connection-service.mjs:
  Added validation, locking, version checks, persistence, disk reload, verification,
  and rollback orchestration, idempotent replay path for an already stored version,
  connect/rotate/disconnect consumer-side handling, and non-secret response projections.
- packages/backend/convex/s3Connections.ts:
  Added initial control-plane implementation for consumer registration, scoped credential
  staging, delivery, retry, rotation, connection status, promotion, and revocation, along
  with initial audit calls and authorization checks.

4. EXISTING FILES MODIFIED
- backend-echo/server.mjs:
  Added imports for consumer configuration service, dedicated S3_CONNECTION_SECRET setting,
  constant-time secret comparison rejecting missing secrets, bounded JSON parsing for
  credential delivery requests, POST /s3-connections/apply, GET /s3-connections for
  non-secret configuration metadata, fail-closed proxy/job shared-secret checks, and generic
  outer HTTP error response.
- packages/backend/convex/schema.ts:
  Added s3Connections table with workspace/account/bucket ownership, consumer/connection
  identifiers, active and pending credential IDs, version, status, error code, and timestamps.
  Added indexes for workspace, account, connection, and credentials.
