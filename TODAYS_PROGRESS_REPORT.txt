======================================================================
1. OBJECTIVE
======================================================================
Implement a workflow that creates narrowly scoped application-issued S3
credentials, securely delivers them to a registered external consumer,
persists and reloads its configuration, verifies gateway connectivity,
and supports safe retry and rotation without manual credential copying.

The concrete consumer selected for this implementation is backend-echo.
This work does not automatically configure arbitrary applications, AWS CLI,
or rclone.

======================================================================
2. ANALYSIS AND ARCHITECTURE COMPLETED
======================================================================
Reviewed the credential lifecycle, Convex schema and authorization helpers,
SigV4 gateway, signing primitives, existing RustFS client, credential UI,
reference backend, package configuration, and existing test fixtures.

Confirmed the distinction between:
- Application-issued S3 access keys: authenticate against the /s3 gateway.
- Dashboard/platform API keys: separate from S3 credentials.
- Server-side RustFS credentials: used by the gateway upstream and not
  intended for disclosure to external applications.

Confirmed that Convex cannot directly edit another host's configuration.
The proposed integration therefore uses authenticated server-to-server
credential delivery to a consumer-owned configuration service.

The existing RustFS client replaces URL paths, so it cannot be used
unchanged for a gateway endpoint containing /s3. A consumer gateway client
was started using the existing SigV4 signing primitives.

Planning is recorded in:
  .planning/automatic-s3-connections.md
